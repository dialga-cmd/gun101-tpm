# Threat Model — GUN-101-TPM

## Threats and Mitigations

| Threat | Mitigation | Code Reference |
|--------|-----------|----------------|
| **TPM-unbound decryption**<br>An attacker with the correct password but a different machine attempts to decrypt the file. | TPM seal binds the DEK to the original TPM. The `unseal_from_tpm()` function requires the TPM to unseal the DEK. Without the matching TPM, the unseal operation fails. | `handler.py:encrypt_file()` seals DEK to TPM via `seal_to_tpm()`<br>`handler.py:decrypt_file()` obtains DEK ONLY via `unseal_from_tpm()` |
| **Password-only decryption**<br>An attacker with the correct password attempts to decrypt without TPM access. | The password-derived KEK is used as the TPM object's auth value (`TPM2B_AUTH(value=kek)`), so both the password AND the TPM are required to unseal. | `tpm.py:seal_to_tpm()` and `unseal_from_tpm()` use `password_auth` as `TPM2B_AUTH`<br>`handler.py:derive_key()` derives KEK from password |
| **TPM fingerprint spoofing**<br>An attacker modifies the TPM fingerprint in the container to bypass machine binding. | The `decrypt_file()` function checks `container["tpm_fingerprint"]` against the current TPM's fingerprint early, before any TPM operation. If they don't match, decryption fails immediately. | `handler.py:decrypt_file()` lines 106-112 — fingerprint check before unseal |
| **Ciphertext tampering**<br>An attacker modifies the encrypted file content to cause unintended behavior. | File data is encrypted with AES-256-GCM. Any modification to the ciphertext or tag is detected during decryption, and `aes_decrypt()` raises `ValueError`. | `handler.py:aes_decrypt()` GCM authentication check<br>`handler.py:decrypt_file()` line 142-146 |
| **Keyless unseal via KEK-encrypted container**<br>An older or alternate implementation stores the KEK-encrypted DEK in the container, allowing decryption with only the password. | The container no longer stores KEK-encrypted DEK fields (`dek_nonce`, `dek_ciphertext`, `dek_tag`). The DEK is obtained exclusively via TPM unseal. | `handler.py:encrypt_file()` — container fields cleaned<br>`handler.py:decrypt_file()` — DEK obtained only from `unseal_from_tpm()` |
| **Weak password derivation**<br>An attacker uses brute-force or dictionary attacks against the password. | Argon2id key derivation with configurable cost parameters (time cost, memory cost, parallelism) from OWASP-recommended minimums. | `kdf.py:derive_key()` — Argon2id with configurable parameters<br>`config.py:ARGON2_TIME_COST`, `ARGON2_MEMORY_COST`, `ARGON2_PARALLELISM` |
| **Side-channel leakage from key comparison**<br>An attacker leverages timing differences in key comparison to derive the password. | `verify_key()` uses `hmac.compare_digest()` for constant-time comparison, preventing timing attacks based on key similarity. | `kdf.py:verify_key()` — `hmac.compare_digest()`<br>`kdf.py:_constant_time_compare()` deprecated in favor of `hmac.compare_digest()` |
| **Environment variable password exposure**<br>The `GUN101TPM_PASSWORD` env var stores the password in shell history or process listings. | Documentation includes a visible warning when the env var path is used. Users are advised to use interactive prompt instead. | `cli.py:get_password()` — env var fallback with warning |
| **TPM unseal failure on wrong machine**<br>An user attempts to decrypt on a different machine and expects it to work. | Decryption explicitly fails with a clear error message: "This file was encrypted on a different machine and cannot be decrypted here. GUN-101-TPM files are hardware-bound." | `handler.py:decrypt_file()` lines 107-112 |
| **No key recovery if TPM fails**<br>TPM hardware fails or is replaced, resulting in permanent loss of encrypted files. | Documentation explicitly warns: "If your machine's TPM fails or you lose the machine, you cannot recover your files." No backup mechanism exists. | `docs/SECURITY.md` — "TPM failure loss" section |
| **No quantum-resistant protection**<br>AES-256 provides ~128-bit post-quantum security, and TPM sealing varies by vendor. | Users are warned about post-quantum limitations. For long-term archival, consider alternative approaches. | `docs/SECURITY.md` — "Not quantum-resistant" section |
